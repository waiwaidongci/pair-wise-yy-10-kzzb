# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用（脚本为普通外链 JS，无需构建，file:// 下可用）。

## 已实现闭环

- 新增作品并记录胎体、纹样、线条、贴线进度、阴干日期、金粉状态和交付日期。
- 工序看板覆盖贴线中、待阴干、上金粉、待交付。
- 今日待阴干、缺陷作品、最近交付三类列表。
- 可更新状态、记录断线/翘线（含位置与修整完成标记）、查看作品详情。
- 支持筛选、交付排序、localStorage 持久化和 JSON 导出。

## 客户验稿（补验稿）

交付前客户先看照片、再到店签字，验稿流程独立成单，不再依赖备注：

- **每件作品至多一张未结束的验稿单**，开单时登记客户姓名与到店时间，进入「待验」队列（带排队号）。
- **签收硬条件：贴线进度 100% 且没有未处理的断线、翘线。** 签收判定通过 → 「已确认」并记录签字人与签字时间；不通过 → 停在「待修整」，列出未通过原因。
- 待修整作品登记缺陷修整后「重新排队」回到待验，重新接受签收判定。
- **签字后**若更换胎体、纹样或线条，或**补记断线**：原确认自动作废并新开一张待验单重新排队；**旧签字连同作废原因留在作品履历**，新单沿用客户姓名、到店时间需重新登记。
  - 补记翘线不自动作废（规则仅断线），但会拦截下一次签收。
- 客户验稿看板分「待验 / 待修整 / 已确认」三列，并可按客户、纹样、胎体筛选。

## 代码分层（三部分分开承载）

| 文件 | 职责 |
| --- | --- |
| `js/store.js` | 作品数据层：localStorage 持久化，作品与缺陷（断线/翘线）增改，旧版自由文本缺陷自动迁移 |
| `js/inspection.js` | 验稿判定层：验稿单状态机（待验/待修整/已确认）、签收条件、作废与重新排队规则；纯业务规则，不碰 DOM |
| `js/app.js` | 页面操作层：渲染、事件、工序看板与验稿看板，调用前两层完成操作 |

## 数据格式

localStorage 键 `zfl42Works`，结构 `{ version: 2, works: [...] }`；每张作品的 `sheets` 保存全部验稿单（含已作废单与旧签字），`defects` 为结构化缺陷记录。
